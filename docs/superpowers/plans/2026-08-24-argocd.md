# ArgoCD GitOps (Platform Layer, Part 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install a trimmed, resource-budgeted ArgoCD + Sealed Secrets
into a cluster and prove ArgoCD syncs `deploy/helm/cloudlite` from this
real git repo — including secrets — with zero manual `helm` commands,
and that a real `git push` alone drives a real deployment change.

**Architecture:** Two official upstream manifests (Sealed Secrets,
ArgoCD), each trimmed/patched via a small verified Python filter
script rather than hand-edited. The two existing plain `Secret`
templates become `SealedSecret` templates (static, pre-sealed
ciphertext — no more `values-secrets.yaml`). One ArgoCD `Application`
resource, authenticated to the real GitHub repo via an SSH deploy key
(substituting for the spec's fine-grained PAT, which can't be created
non-interactively in this environment — same purpose, different
mechanism, already approved).

**Tech Stack:** ArgoCD v3.5.1, Sealed Secrets v0.39.1, Helm 3, k3d
(real k3s in Docker), `kubeseal`, `gh` CLI.

**Spec:** [`docs/superpowers/specs/2026-08-24-argocd-design.md`](../specs/2026-08-24-argocd-design.md)

## Global Constraints

- ArgoCD install manifest source: `https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.1/manifests/install.yaml`.
  Remove `argocd-dex-server`, `argocd-notifications-controller`,
  `argocd-applicationset-controller` and their supporting objects only
  — never the `applicationsets.argoproj.io` CRD (harmless unused).
- Sealed Secrets install manifest source: `https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.39.1/controller.yaml`
  (a release asset — `raw.githubusercontent.com/.../controller.yaml`
  404s, it is not a repo file at that path).
- `kubeseal` client: `https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.39.1/kubeseal-0.39.1-linux-amd64.tar.gz`.
- This sandbox's Docker host is cgroup v1
  (`docker info | grep -i cgroup` → `Cgroup Version: 1`) — k3d cluster
  creation must pin `--image rancher/k3s:v1.28.15-k3s1` or the kubelet
  fails to start (documented in `docs/platform/helm-charts.md`'s known
  issues from the Helm chart sub-project).
- **Deviation from spec, approved:** ArgoCD's repo credential is an SSH
  deploy key (generated fresh, registered read-only via `gh api`,
  deleted during cleanup), not the spec's fine-grained PAT — a
  fine-grained PAT cannot be created non-interactively in this
  environment. Same purpose and lifecycle as the spec's mechanism.
- **Deviation from spec, approved:** the GitOps-loop-proof step (Task
  5) uses a locally-built, `k3d image import`-ed image rather than
  pulling the real private `ghcr.io/aliffaizuddin/aws/s3` image —
  pulling a private GHCR image needs a `read:packages`-scoped
  credential, which also requires interactive browser auth to create.
  Fully proves the same mechanism (a git-committed tag change drives a
  real ArgoCD sync and pod roll); pulling the real registry image
  becomes a documented open item for the real bare-metal deployment.
- The k3d cluster is environment setup, not a plan task: the
  controller creates it once, before Task 1, and it stays alive across
  Tasks 1-5, torn down only at the end of Task 5. Every implementer
  task brief below states this as a precondition — no task creates or
  destroys the cluster itself.
- Repo: `https://github.com/aliffaizuddin/AWS.git` (SSH:
  `git@github.com:aliffaizuddin/AWS.git`), owner `aliffaizuddin`,
  private.

**Files:**

**Interfaces:**

- [ ] **Step 1: Download the upstream manifest**

```bash

```

- [ ] **Step 2: Write and run the trim/patch script**

Save as `/tmp/trim_sealed_secrets.py`:

```python
import yaml

SOURCE_URL = "https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.39.1/controller.yaml"

with open("/tmp/sealed-secrets-v0.39.1.yaml") as f:
    docs = list(yaml.safe_load_all(f))

for d in docs:
    if not d:
        continue
    if d.get("metadata", {}).get("namespace") == "kube-system":
        d["metadata"]["namespace"] = "sealed-secrets"
    if d.get("kind") in ("RoleBinding", "ClusterRoleBinding"):
        for s in d.get("subjects", []):
            if s.get("namespace") == "kube-system":
                s["namespace"] = "sealed-secrets"
    if d.get("kind") == "Deployment":
        for c in d["spec"]["template"]["spec"]["containers"]:
            if c["name"] == "sealed-secrets-controller":
                c["resources"] = {
                    "requests": {"cpu": "50m", "memory": "64Mi"},
                    "limits": {"cpu": "100m", "memory": "128Mi"},
                }

with open("deploy/argocd/install/sealed-secrets-install.yaml", "w") as f:
    f.write(f"# Derived from {SOURCE_URL}\n")
    f.write("# Rewrote namespace kube-system -> sealed-secrets throughout.\n")
    f.write("# Added explicit resources.requests/limits to the controller container.\n")
    yaml.dump_all([d for d in docs if d], f, default_flow_style=False, sort_keys=False)

print("total docs written:", len([d for d in docs if d]))
```

Run: `python3 /tmp/trim_sealed_secrets.py`
Expected output: `total docs written: 11`

### Task 3: Trimmed, resource-budgeted ArgoCD install

**Files:**
- Create: `deploy/argocd/install/argocd-install.yaml`

**Interfaces:**
- Produces: a running ArgoCD (4 components only) in the `argocd`
  namespace, with the `Application` CRD available. Task 4 consumes
  this to create and apply the `cloudlite` `Application`.

- [ ] **Step 1: Download the upstream manifest**

```bash

```

- [ ] **Step 2: Write and run the trim/patch script**

Save as `/tmp/trim_argocd.py`:

```python
import yaml

SOURCE_URL = "https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.1/manifests/install.yaml"

REMOVE_NAMES = {
    "argocd-applicationset-controller",
    "argocd-dex-server",
    "argocd-notifications-controller",
    "argocd-notifications-cm",
    "argocd-notifications-secret",
    "argocd-notifications-controller-metrics",
    "argocd-applicationset-controller-network-policy",
    "argocd-dex-server-network-policy",
    "argocd-notifications-controller-network-policy",
}

RESOURCES = {
    "argocd-application-controller": {"requests": {"cpu": "250m", "memory": "256Mi"}, "limits": {"cpu": "500m", "memory": "512Mi"}},
    "argocd-repo-server": {"requests": {"cpu": "100m", "memory": "128Mi"}, "limits": {"cpu": "300m", "memory": "384Mi"}},
    "argocd-server": {"requests": {"cpu": "50m", "memory": "64Mi"}, "limits": {"cpu": "150m", "memory": "192Mi"}},
    "redis": {"requests": {"cpu": "50m", "memory": "64Mi"}, "limits": {"cpu": "100m", "memory": "128Mi"}},
}

with open("/tmp/argocd-v3.5.1.yaml") as f:
    docs = list(yaml.safe_load_all(f))

kept = []
for d in docs:
    if not d:
        continue
    if d["metadata"]["name"] in REMOVE_NAMES:
        continue
    if d.get("kind") in ("Deployment", "StatefulSet"):
        for c in d["spec"]["template"]["spec"]["containers"]:
            if c["name"] in RESOURCES:
                c["resources"] = RESOURCES[c["name"]]
    kept.append(d)

with open("deploy/argocd/install/argocd-install.yaml", "w") as f:
    f.write(f"# Derived from {SOURCE_URL}\n")
    f.write("# Removed: argocd-dex-server, argocd-notifications-controller, argocd-applicationset-controller\n")
    f.write("# (and their supporting ServiceAccount/Role/RoleBinding/ClusterRole/ClusterRoleBinding/ConfigMap/Secret/Service/NetworkPolicy objects)\n")
    f.write("# Added explicit resources.requests/limits to the 4 kept components.\n")
    yaml.dump_all(kept, f, default_flow_style=False, sort_keys=False)

print("kept:", len(kept))
```

Run: `python3 /tmp/trim_argocd.py`
Expected output: `kept: 37`

# ArgoCD GitOps

**Status:** built — a trimmed, resource-budgeted ArgoCD install (4 of
7 stock components: application-controller, repo-server, server,
redis) plus Sealed Secrets, syncing `deploy/helm/cloudlite` from this
repo automatically. See
[`../superpowers/plans/2026-08-24-argocd.md`](../superpowers/plans/2026-08-24-argocd.md)
for what was built and
[`../superpowers/specs/2026-08-24-argocd-design.md`](../superpowers/specs/2026-08-24-argocd-design.md)
for the design.

## Scope

- `deploy/argocd/install/argocd-install.yaml` — ArgoCD v3.5.1, trimmed
  (no dex/notifications/applicationset-controller — no SSO, no
  alerting, no ApplicationSet use here), with explicit
  `resources.requests/limits` on all 4 kept components.
- `deploy/argocd/install/sealed-secrets-install.yaml` — Sealed Secrets
  v0.39.1, installed into its own `sealed-secrets` namespace (the
  upstream manifest defaults to `kube-system`) with explicit resource
  limits.
- `deploy/helm/cloudlite`'s two secrets (`postgres-credentials`,
  `iam-jwt-secret`) are now `SealedSecret` resources — ciphertext safe
  to commit, decrypted in-cluster by the controller. This replaces
  `values-secrets.yaml`/`.example` entirely; there is no more
  `required()` guard on either secret.
- `deploy/argocd/applications/cloudlite.yaml` — the one `Application`,
  `syncPolicy.automated: {prune: true, selfHeal: true}`, watching
  `deploy/helm/cloudlite` on `main`.
- Repo access: a read-only SSH deploy key (not the fine-grained PAT the
  design spec originally called for — creating one non-interactively
  isn't possible in this environment; a deploy key is the automatable
  equivalent, same purpose and lifecycle).

## Bootstrap order (one-time, not GitOps-managed)

Install Sealed Secrets → install ArgoCD → apply the repo-credentials
`Secret` into `argocd` → apply
`deploy/argocd/applications/cloudlite.yaml`. From that point on,
ArgoCD's own reconciliation loop is the only thing that should touch
the `cloudlite` namespace.

## Validated against

A local k3d cluster (real k3s in Docker), the same sandbox stand-in
used for the Helm chart sub-project. Confirmed for real: ArgoCD clones
this actual GitHub repo (not a local path) and syncs the chart with
zero manual `helm` commands; both `SealedSecret`s decrypt to the
correct values; a real `git push` bumping `values.yaml`'s image tag
drives an automatic pod rollout with no `kubectl`/`helm` command
involved; and `syncPolicy.automated.selfHeal` reverts a manually
`kubectl scale`d Deployment back to what git specifies.

## Known operational properties (not defects)

- **Re-sealing on cluster change:** `SealedSecret` ciphertext is
  cryptographically bound to the sealing cluster's key. Pointing this
  chart at a different cluster (a fresh k3d instance, or the real
  bare-metal node) means re-running `kubeseal` and committing the new
  ciphertext — this is how Sealed Secrets is designed to work, not a
  bug to fix.
- **The GitOps-loop-proof step used a locally-built, `k3d
  image import`-ed image, not the real `ghcr.io/aliffaizuddin/aws/s3`
  image** — pulling the real private GHCR image needs a registry pull
  credential, and creating one (a token with `read:packages` scope)
  also requires interactive browser auth, unavailable in this sandbox.
  The sync mechanism this proves is identical either way; wiring up a
  real registry pull credential (or making the GHCR packages public)
  is an open item for whoever deploys this to real hardware.

## Out of scope

Automating the image-tag bump (e.g. ArgoCD Image Updater) — stays a
human edit + commit for now. HashiCorp Vault or any secrets manager
beyond Sealed Secrets. An app-of-apps pattern (only one `Application`
exists). ArgoCD's own install being itself GitOps-managed. TLS/ingress
exposure of the ArgoCD UI. Observability, chaos test (separate, later
sub-projects). Actually running this against the user's real
bare-metal node.
